# 跨机构数据协作台账

本服务记录数据来源、字段含义、合作许可、数据产品及交付凭据。合作方可在本地演练不同机构和法域之间的资料流转；示例记录均为虚构，不连接真实口岸或支付系统。

需要 Python 3.10 或更新版本，不依赖第三方包。

运行项目测试：`python -m unittest discover -s tests -v`。
检查源码：`python -m compileall -q exchange`。
演练入口：`python -m exchange --database demo.db`。

领域逻辑分布在来源目录、合作许可、产品编排和交付核验中。`exchange/service.py` 组合这些操作，`exchange/db.py` 保存本地 SQLite 表结构；调用接口和现有边界可从源码及测试读取。

## 授权链

合作许可构成可追溯的授权链，而不仅是来源方到最终接收方的直接许可：

- 用途需先登记（`grants.define_purpose`），可声明上级用途形成层级，例如「供应链协调·报关」是「供应链协调」的细分。
- 来源方签发根许可（`grants.issue`），`delegable=True` 才允许接收方再转授；中间机构以 `parent` 指向上游许可签发下游许可，签发时校验：转授方必须是上游接收方、上游允许转授且未撤销、用途逐级缩窄或不变、有效期不超出上游。
- 交付时（`delivery.send`）沿链从根到最终接收方逐级核验每一环的授予方、接收方、用途覆盖、有效期与撤销状态。允许交付的那条链快照存入交付凭据；任一环不满足即拒绝，拒绝原因携带完整链路轨迹，可说明是哪一环、因什么拦下了流转。
- `grants.revoke` 撤销任一环后，其下游许可一并失效，尚未完成的下游交付会在核验处被拦下；已落账的交付保留当时的授权依据，用 `delivery.explain` 可对照每一环的当前状态（撤销、过期），标出后续影响。
